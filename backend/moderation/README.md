# 博客内容审核算法

本实现是可训练、可复核的课程演示系统。默认语料覆盖风险营销和人身攻击，不能据此声称具备完整的内容合规判断能力。

## 算法路线

1. 对标题、正文和标签分别切分。正文按段落处理，长段落使用360字符窗口、60字符重叠，保留原文偏移。
2. NFKC标准化、英文小写、清除零宽字符；字符二元组和三元组不跨标点边界。
3. 从训练集建立最多512项词表和IDF，使用子线性TF与L2归一化。追加承诺、招揽、联系方式、组合、警示语境、异常字符、链接和重复特征。
4. 使用ml-logistic-regression训练二分类模型。概率形式的输出仅作为未校准的风险分值；可以查看正向特征贡献。
5. 通过同窗口的组合与防范语境提供辅助证据。警示词不会把整篇文章放行；引用和代码也不会自动免审。当前语境判断是局部特征，尚未实现独立语义模型。
6. 记录最高分、前三窗口均分和高风险窗口比例。第一版以最高分保留局部风险；无警示语境的高风险组合触发暂缓发布。其他聚合量用于解释和后续实验，不伪装成已训练的第二层模型。重叠证据合并。
7. 验证集选择人工审核阈值；暂缓阈值0.8是初始人工设定。决策为published、pending、held；管理员可published或rejected。
8. 复核使用版本号防止批准已被修改的文章，数据库触发器原子保存标签、原文快照和日志。编辑后重新审核，旧文章默认保留已发布状态。首次通过时发放发布奖励。

## 训练与评价

在backend目录运行：

```sh
npm run moderation:train
npm test
```

训练产生`model.json`和`evaluation.json`，比较关键词基线、多项式朴素贝叶斯与分段逻辑回归方案，报告Precision、Recall、F1、转人工比例、违规自动通过比例。训练词表只使用train，阈值只使用validation，test不参与调参。

默认数据是手写演示样例：40条训练、12条验证、12条测试。测试结果只证明流程可运行；样本少且表达相近，不代表真实泛化能力。未实现概率校准，不输出“真实违规概率”。

可传入自行整理的JSON数组：

```sh
npm run moderation:train -- path/to/curated-windows.json
```

每项格式如下，text代表人工标注的局部片段：

```json
{"id":"article-42-window-0","text":"人工标注片段","label":0,"split":"train"}
```

label为0正常、1违规；split为train、validation或test，各集合需有两种标签。完全重复的标准化文本会被拒绝。近似文章、同一文章的窗口、同模板样本必须人工分组放入同一个集合；当前没有自动近似去重。

管理员在发布审核页面导出反馈。导出是文章级标签和复核快照，需人工整理片段标签、剔除错误标注并分组划分，再重新训练；不能把违规文章的所有正常段落都标为违规。重训后重启后端加载新模型，不自动覆盖已有审核结果。

## 后续实验

收集实际样本后，依次对比去除结构特征、去除上下文特征、整篇与分段、关闭组合规则的结果。再考虑概率校准、学习文章级聚合模型和独立语境分类器。随机抽查已发布内容可补充漏判样本，后台支持对已发布文章复核。

## 接口与页面

- 作者：`GET /api/articles/mine/submissions`，草稿与投稿页面查看状态，详情页面可修改后重新提交。
- 管理员：`GET /api/admin/moderation?status=review`，review包括pending和held；也可单选pending、held、rejected、published，省略表示全部。页面最多返回200条，后续应增加分页。
- 复核：`PATCH /api/admin/moderation/:id`，字段decision、revision、reason。过期版本返回409。
- 导出：`GET /api/admin/moderation/feedback/export`。
- 创建、编辑、草稿发布均执行审核。公开列表、搜索、详情、个人主页、系列、收藏、标签、阅读互动和成就计数只使用已发布内容。

文本模型不分析图片与封面内容；此处仅完成文本发布审核。
